                                                Testing the Admin/Lead Management API
POST /api/admin/lead - Create a new lead.
Headers:
{
  "Authorization": "Bearer <your_token_here>",
  "Content-Type": "application/json"
}
Body (raw JSON):
{
  "clientId": "6622ea36567d4630f4d7f7c5",
  "photographerId": "662a3f7becc2c66c56d93e21"
}

GET /api/admin/leads - Get all leads.
Headers:
{
  "Authorization": "Bearer <your_token_here>"
}
This will return a list of all leads with populated clientId and photographerId.

PUT /api/admin/lead/status - Update the status of a lead.
Headers:
{
  "Authorization": "Bearer <your_token_here>",
  "Content-Type": "application/json"
}
Body (raw JSON):
{
  "leadId": "68049716559ce16666f24c09",
  "status": "completed"
}
✅ Valid statuses: "pending", "assigned", "completed"

Notes
Make sure the JWT token is valid (not expired).
Ensure that the IDs (clientId, photographerId, leadId) exist in your MongoDB.
If you don’t yet have a photographer model or registration, you can mock one in MongoDB temporarily using MongoDB Compass or an admin API.
